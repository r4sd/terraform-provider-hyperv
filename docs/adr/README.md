# Architecture Decision Records

このディレクトリは **「なぜそう決めたか」** を残す場所。現行のルールや手順は置かない。

| 置き場所 | 内容 | 性質 |
|---|---|---|
| `CLAUDE.md` | 今どう開発するか(シャドウ移行の DoD・feature flag) | **常に最新だけ**。古い記述は上書きする |
| `docs/adr/` | なぜそう決めたか(判断・根拠・却下案) | **追記のみ**。過去の判断を消さない |
| `docs/resources/`, `docs/data-sources/` | Terraform リソースのリファレンス | 常に最新だけ |

> **`docs/adr/` は `CLAUDE.md` を置き換えない。**
> 「今どのルールに従うか」は `CLAUDE.md` が唯一の正。ADR はそのルールが**なぜ生まれたか**を記録する。

---

## 運用ルール: 1テーマ1ファイル・追記方式

**1決定1ファイルにしない。** テーマ単位でファイルを作り、決定が変わったら同じファイルに追記する。

理由: 1決定1ファイルは正統な ADR 方式だが、この規模でも年に数十個まで増えて管理不能になる。
テーマ単位なら **5〜8 ファイル**で数年運用できる。

### 追記のしかた

- 新しい決定は **ファイル末尾に日付付きで追記**する
- 過去の決定は**書き換えない**。撤回する場合は「## YYYY-MM-DD: 〜を撤回」と新セクションを足し、
  旧セクションの冒頭に `> ⚠️ この判断は YYYY-MM-DD に撤回(下記参照)` を1行足すだけにとどめる
- 「現在の結論」はファイル冒頭の **## 現在の決定** に置き、ここだけは上書きしてよい

## 記述上の注意

このリポジトリは公開されている。**実環境のアドレス・ホスト名・アカウント名・VM 名を書かない。**
例示が必要なときは RFC 5737 の文書用アドレスかプレースホルダを使う。
CI がプライベートアドレスの混入を落とす(`.github/workflows/security.yml` の `no-private-addresses`)。

## アーカイブ方針

**当面は不要。** 15 ファイルを超えたら、以下を**すべて**満たすものだけ `docs/adr/archive/` へ移す。

- その判断の対象が実装から消えている
- 現行の判断に影響しない(他の ADR から参照されていない)
- 1 年以上更新がない

移動する際は索引に「(archived)」として行を残し、リンクは切らない。
**経緯を辿れなくすることが最大の損失**なので、容量を理由に消さない。
